# Docker Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a complete, production-capable Docker Compose environment for AI Chat Herder covering backend (.NET 10), frontend (Angular 21 + Nginx), PostgreSQL 17, Redis 7, and RabbitMQ 3.13.

**Architecture:** Multi-stage Docker builds keep final images lean (SDK excluded from runtime). Nginx in the frontend container reverse-proxies `/api/` and `/hubs/` to the backend, eliminating CORS. All services communicate via a dedicated Docker bridge network using container-name DNS. Environment variables flow from a single `.env` file — nothing hardcoded.

**Tech Stack:** .NET 10 SDK + ASP.NET Runtime, Node 22 Alpine + Nginx Alpine, PostgreSQL 17 Alpine, Redis 7 Alpine, RabbitMQ 3.13 Management Alpine.

## Task 1: `Dockerfile.backend` — .NET 10 Multi-stage

**Files:**
- Create: `Dockerfile.backend`

- [ ] **Step 1: Write the file**

```dockerfile
# ─── Stage 1: Build ───────────────────────────────────────────────────────────
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /app

# Copy solution + project files first for Docker layer-cache efficiency
COPY ChatHerder.sln ./
COPY src/ChatHerder.Domain/ChatHerder.Domain.csproj          src/ChatHerder.Domain/
COPY src/ChatHerder.Application/ChatHerder.Application.csproj src/ChatHerder.Application/
COPY src/ChatHerder.Infrastructure/ChatHerder.Infrastructure.csproj src/ChatHerder.Infrastructure/
COPY src/ChatHerder.API/ChatHerder.API.csproj                 src/ChatHerder.API/

RUN dotnet restore

# Copy source and publish
COPY src/ src/
RUN dotnet publish src/ChatHerder.API/ChatHerder.API.csproj \
    -c Release \
    -o /app/publish \
    --no-restore

# ─── Stage 2: Runtime ─────────────────────────────────────────────────────────
FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app

# Non-root user for security
RUN adduser --disabled-password --gecos "" appuser && chown -R appuser /app
USER appuser

COPY --from=build /app/publish .

# ASP.NET Core listens on 8080 by default in container images since .NET 8+
EXPOSE 8080

ENTRYPOINT ["dotnet", "ChatHerder.API.dll"]
```

## Task 2: `frontend/nginx.conf` — SPA Routing + Reverse Proxy

**Files:**
- Create: `frontend/nginx.conf`

- [ ] **Step 1: Write the file**

```nginx
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    # Gzip static assets
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;

    # Angular SPA — all unknown paths fall back to index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Reverse-proxy REST API to backend (same-origin from browser perspective)
    location /api/ {
        proxy_pass         http://backend:8080/api/;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        # Needed for file uploads
        client_max_body_size 25M;
    }

    # Reverse-proxy SignalR WebSocket hubs (WebSocket upgrade required)
    location /hubs/ {
        proxy_pass         http://backend:8080/hubs/;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade    $http_upgrade;
        proxy_set_header   Connection "upgrade";
        proxy_set_header   Host       $host;
        proxy_read_timeout 86400s;  # Keep WebSocket alive
    }

    # Cache static assets aggressively
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

**Why `client_max_body_size 25M`:** AGENT.md §13 specifies a 20 MB file upload limit. Nginx default is 1 MB and would reject uploads before they reach the backend. 25 MB gives 5 MB headroom for multipart overhead.

## Task 3: `frontend/Dockerfile` — Angular 21 Multi-stage

**Files:**
- Create: `frontend/Dockerfile`

**Note on output path:** Angular 21 with SSR outputs to `dist/<project-name>/browser`. Without SSR it outputs to `dist/<project-name>`. This Dockerfile targets a pure SPA (no SSR) with `ng build --configuration production`. Adjust `COPY --from=build` path if your `angular.json` `outputPath` differs.

- [ ] **Step 1: Write the file**

```dockerfile
# ─── Stage 1: Build ───────────────────────────────────────────────────────────
FROM node:22-alpine AS build
WORKDIR /app

# Copy manifests first for npm cache layer
COPY package.json package-lock.json ./
RUN npm ci --prefer-offline

# Copy source and build for production
COPY . .
RUN npm run build -- --configuration production

# ─── Stage 2: Serve ───────────────────────────────────────────────────────────
FROM nginx:alpine AS runtime

# Remove default Nginx config
RUN rm /etc/nginx/conf.d/default.conf

COPY nginx.conf /etc/nginx/conf.d/default.conf

# Angular production build output — adjust '<project-name>' to match angular.json
# Typical: dist/chat-herder or dist/frontend
COPY --from=build /app/dist/chat-herder /usr/share/nginx/html

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

- [ ] **Step 2: Verify the COPY path matches angular.json**

When the Angular project is scaffolded, check:

```bash
cat frontend/angular.json | python3 -c "import sys,json; d=json.load(sys.stdin); print(list(d['projects'].values())[0]['architect']['build']['options']['outputPath'])"
```

Update the `COPY --from=build` line in `frontend/Dockerfile` to match the reported `outputPath`.

## Task 4: `docker-compose.yml`

**Files:**
- Create: `docker-compose.yml`

- [ ] **Step 1: Write the file**

```yaml
# docker-compose.yml — AI Chat Herder
# Copy .env.template → .env and fill in secrets before running.

services:

  # ── PostgreSQL 17 ────────────────────────────────────────────────────────────
  postgres:
    image: postgres:17-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB:       ${POSTGRES_DB}
      POSTGRES_USER:     ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - chatnet
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s

  # ── Redis 7 ──────────────────────────────────────────────────────────────────
  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: redis-server --appendonly yes --requirepass ${REDIS_PASSWORD}
    volumes:
      - redis_data:/data
    networks:
      - chatnet
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5

  # ── RabbitMQ 3.13 ────────────────────────────────────────────────────────────
  rabbitmq:
    image: rabbitmq:3.13-management-alpine
    restart: unless-stopped
    environment:
      RABBITMQ_DEFAULT_USER: ${RABBITMQ_USER}
      RABBITMQ_DEFAULT_PASS: ${RABBITMQ_PASSWORD}
      RABBITMQ_DEFAULT_VHOST: ${RABBITMQ_VHOST}
    volumes:
      - rabbitmq_data:/var/lib/rabbitmq
    networks:
      - chatnet
    ports:
      - "15672:15672"   # Management UI (dev convenience — remove in production)
    healthcheck:
      test: ["CMD", "rabbitmq-diagnostics", "ping"]
      interval: 15s
      timeout: 10s
      retries: 5
      start_period: 30s

  # ── Backend (.NET 10) ─────────────────────────────────────────────────────────
  backend:
    build:
      context: .
      dockerfile: Dockerfile.backend
    restart: unless-stopped
    environment:
      ASPNETCORE_ENVIRONMENT: ${ASPNETCORE_ENVIRONMENT}
      ASPNETCORE_URLS: http://+:8080

      # Connection strings — use container-name DNS (never "localhost")
      ConnectionStrings__DefaultConnection: >-
        Host=postgres;Port=5432;Database=${POSTGRES_DB};
        Username=${POSTGRES_USER};Password=${POSTGRES_PASSWORD};
        Include Error Detail=true
      ConnectionStrings__Redis: >-
        redis,password=${REDIS_PASSWORD},abortConnect=false

      # RabbitMQ
      RabbitMQ__Uri: amqp://${RABBITMQ_USER}:${RABBITMQ_PASSWORD}@rabbitmq:5672/${RABBITMQ_VHOST}

      # JWT
      Jwt__SecretKey:  ${JWT_SECRET_KEY}
      Jwt__Issuer:     ${JWT_ISSUER}
      Jwt__Audience:   ${JWT_AUDIENCE}

      # File storage (mapped to the uploads volume mount path)
      Storage__BasePath: /app/uploads

      # SMTP (password reset)
      Smtp__Host:     ${SMTP_HOST}
      Smtp__Port:     ${SMTP_PORT}
      Smtp__Username: ${SMTP_USERNAME}
      Smtp__Password: ${SMTP_PASSWORD}
      Smtp__FromAddress: ${SMTP_FROM_ADDRESS}
    volumes:
      - uploads:/app/uploads
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
      rabbitmq:
        condition: service_healthy
    networks:
      - chatnet
    expose:
      - "8080"   # Internal only — accessed via frontend Nginx reverse proxy

  # ── Frontend (Angular 21 + Nginx) ─────────────────────────────────────────────
  frontend:
    build:
      context: frontend
      dockerfile: Dockerfile
    restart: unless-stopped
    ports:
      - "80:80"      # Production port
      - "4200:80"    # Also exposed on Angular's conventional dev port
    depends_on:
      - backend
    networks:
      - chatnet

# ── Named Volumes ─────────────────────────────────────────────────────────────
volumes:
  postgres_data:
    driver: local
  redis_data:
    driver: local
  rabbitmq_data:
    driver: local
  uploads:
    driver: local           # Persistent file uploads (IFileStorage / LocalFileStorage)

# ── Network ───────────────────────────────────────────────────────────────────
networks:
  chatnet:
    driver: bridge
```

- [ ] **Step 1: Write the file**

```markdown
# Docker Setup — AI Chat Herder

## Prerequisites

- Docker ≥ 25 with Compose V2 (`docker compose` not `docker-compose`)
- 4 GB free RAM (PostgreSQL + Redis + RabbitMQ + .NET runtime + Nginx)

## Quick Start

```bash
# 1. Copy and fill in secrets
cp .env.template .env
# Edit .env — replace every <CHANGE_ME> value

# 2. Build and start all services
docker compose up --build -d

# 3. Verify all services are healthy
docker compose ps

# 4. View backend logs (EF Core migration output visible here)
docker compose logs -f backend
```

## Services and Ports

| Service | Internal Port | Exposed Port | URL |
|---------|--------------|--------------|-----|
| frontend (Nginx) | 80 | 80, 4200 | http://localhost |
| backend (.NET) | 8080 | — (internal only) | via Nginx proxy |
| postgres | 5432 | — | — |
| redis | 6379 | — | — |
| rabbitmq | 5672 | 15672 (mgmt) | http://localhost:15672 |

The frontend container proxies `/api/*` and `/hubs/*` to the backend. Direct browser calls always go through `http://localhost`.

## File Upload Persistence

File uploads are stored in the `uploads` named Docker volume, mounted at `/app/uploads` inside the backend container. This survives container restarts and image rebuilds.

```bash
# Inspect the volume
docker volume inspect ai-chat-herder_uploads
```

## Database Migrations

EF Core migrations run automatically on backend startup (`app.MigrateAsync()` in `Program.cs`). No manual steps required. If a migration fails, check logs:

```bash
docker compose logs backend | grep -i "migration\|error"
```

## Common Operations

```bash
# Rebuild only the backend after code changes
docker compose up --build -d backend

# Reset the database (WARNING: destroys all data)
docker compose down -v
docker compose up --build -d

# Connect to PostgreSQL shell
docker compose exec postgres psql -U chatherder -d chatherder

# Connect to Redis CLI
docker compose exec redis redis-cli -a <REDIS_PASSWORD>

# Open RabbitMQ management console
open http://localhost:15672  # login: RABBITMQ_USER / RABBITMQ_PASSWORD
```

## Generating a JWT Secret

```bash
openssl rand -base64 64
```

Copy the output into `JWT_SECRET_KEY` in `.env`. Do not use a short or dictionary-based secret.

## Stopping

```bash
# Stop services, keep volumes
docker compose down

# Stop services AND delete all data volumes
docker compose down -v
```
